### Verilator command (TinyGPU-ML only)

From the NEORV32 setup directory:

```bash
cd /workspaces/lab_DHWA-main/neorv32-setups/neorv32

verilator -Wall --Wno-fatal --cc \
  --language 1800-2017 \
  -O3 \
  -Mdir obj_dir \
  rtl/core/tinygpu_ml/tinygpu_pkg.sv \
  rtl/core/tinygpu_ml/tinygpu_spm.sv \
  rtl/core/tinygpu_ml/tinygpu_dma.sv \
  rtl/core/tinygpu_ml/tinygpu_array4x4.sv \
  rtl/core/tinygpu_ml/tinygpu_vec_alu.sv \
  rtl/core/tinygpu_ml/tinygpu_epilogue.sv \
  rtl/core/tinygpu_ml/tinygpu_regs.sv \
  rtl/core/tinygpu_ml/tinygpu_cmd_ctrl.sv \
  rtl/core/tinygpu_ml/tinygpu_counters.sv \
  rtl/core/tinygpu_ml/tinygpu_pe.sv \
  rtl/core/tinygpu_ml/tinygpu_top.sv \
  --top-module tinygpu_top \
  --exe sim/tb_tinygpu.cpp
```

Notes:

- `--Wno-fatal` keeps WIDTH/UNUSED/EOFNEWLINE warnings non-fatal so Verilator completes. [web:46][file:4]
- `tinygpu_spm.sv`: reset loops use blocking `=` instead of nonblocking `<=` in `for` loops to avoid `BLKLOOPINIT` errors. [file:4]

### Testbench location and behavior

Testbench path:

```bash
/workspaces/lab_DHWA-main/neorv32-setups/neorv32/sim/tb_tinygpu.cpp
```
[file:3]

Current behavior:

- Drives `clk` / `rst_n` for `tinygpu_top`.
- Programs a **direct-mode VEC_ADD** command via MMIO: sets opcode, dims, strides, addresses, flags, then pulses `start` in `REG_CTRL` with `direct_mode=1` and `irq_enable=1`. [file:5][file:6][file:11]
- Uses a **dummy memory model**:
  - Every cycle: `mem_ready = 1`, `mem_rvalid = 0`, `mem_rdata = 0`. [file:9]
- Polls and prints:
  - `REG_STATUS` decoded as bits  
    `busy(0), done_sticky(1), illegal_opcode(2), shape_error(3), memory_error(4), unsupported_fmt(5), idle=~busy(6)`. [file:5]
  - `REG_IRQ_STATUS` (bit 0 = `irq_pending_q`). [file:5]
- Logs show:
  - At reset: `REGSTATUS = 0x00000040` → `idle=1`, others 0.  
  - After start: `REGSTATUS = 0x00000001` → `busy=1`, no errors, never returns to idle, `IRQST=0`, `irq` never asserts. [file:5][file:11]

Interpretation for the team:

- Command is accepted and engine becomes busy (no illegal/shape/memory/format error bits).
- `cmd_done_i` from `tinygpu_cmd_ctrl` never asserts, so `done_sticky`, `irq_pending`, and `irq` stay low.
- Reason: DMA never sees `mem_rvalid` from the testbench memory, so the command never completes with the current stub. [file:9][file:11]

### Suggested next step

Replace the dummy memory in `sim/tb_tinygpu.cpp` with a small RAM model:

- Keep a `uint32_t ram[]` array.
- On `mem_req && mem_we`: write `mem_wdata` to `ram[mem_addr >> 2]` with `mem_ready=1`.
- On `mem_req && !mem_we`: drive `mem_rdata=ram[mem_addr >> 2]`, assert `mem_rvalid=1` for a cycle (and `mem_ready=1`) so DMA reads can complete. [file:9][file:11]

This should eventually allow `cmd_done_i` to assert, flipping `done_sticky`/`irq_pending` and making `irq` go high on successful command completion.
